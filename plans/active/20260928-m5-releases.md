## Purpose / Big Picture

Four pages still describe the pre-August app:

- **Release overview:** "View a release" says only "a release and its schemas", but the Overview also has the commit, Active and Staged counts, and File Rules, and there's a Stage tab.
- **Duplicate a release:** doesn't say file rules aren't copied. Armel decided this is intended and must be documented.
- **Device history:** says little about the Deployments tab, and describes a config instance panel with Content and Metadata tabs that no longer exist.
- **Compare:** doesn't cover files it can't diff, files whose format changed, or slot names.
- **File rules view:** doesn't list the fields an expanded rule shows, or that upload-only and retention-only rules show only their own fields.

After this milestone, each of those sections matches frontend `origin/prod` and backend `v0.11.9`.

Tags `v0.11.10` to `v0.11.12` exist but aren't in production. Frontend `origin/prod` is still `2b3ffed6`. `git log --since=2026-09-24 origin/prod origin/main` on the releases, deployments, device deployments, compare, diff, file-rules and releases/devices route paths returns nothing.
- **M4 is merged** as #213 (`08f54ae`). Its plan was moved to `plans/completed/` in this branch's first commit, `b1d4160`.
- **The config instance panel lost its tabs.** Clicking a config in a deployment's panel opens the config instance sheet (`src/features/config-instances/components/sheet/*`). It shows the file in **Diff** mode by default, against the same slot in the parent deployment, with **Read-only**, copy and download. There are no Content or Metadata tabs, so `device-history.mdx` → "View a config instance" is wrong, beyond the audit's item 22.
- **Config badges compare with the parent.** In a deployment's panel, each config is **ADDED** (no matching slot in the parent), **UNCHANGED** (same digest), or shows change counts (`M`/`A`/`D` or `+N −M`). **MODIFIED** appears only when counts can't be shown (`src/features/deployments/components/sheet/utils/badge.ts`).
- **The unavailable-diff labels live in `DIFF_UNAVAILABLE_MESSAGE`** (`src/features/editor/utils/errorSummary.ts`): "This file couldn't be parsed." and "Miru couldn't build a diff for this file." A file whose format differs between base and head shows **DIFFERENT FORMAT** and "This file changed format (…); a cross-format diff isn't supported." (`compare/utils/alignFiles.ts`, `FileContent.tsx`).
- **The API can copy file rules; the dialog doesn't.** The frontend API's `CreateReleaseRequest` accepts `file_rule_ids`, but Duplicate sends only `version`, `config_schema_ids` and `git_commit_ref` (`duplicate/api/mutation.ts`). Armel first decided that's intended, then reversed it at ENG-1399: it's a bug, filed as ENG-1427 (M9).
- **A release opens on Stage, not Overview.** `DEFAULT_RELEASE_TAB = 'stage'` (`releases/hooks/useReleaseLastTab.ts:7`); after that the list opens the last tab used (`list/hooks/useReleasesList.ts:141`).
- **Active counts devices queued for the release too.** It filters on the device's target deployment (`backend internal/configs/db/device.go:353-398`). Staged is one per device: staging archives the device's earlier staged deployment (`services/deployments/create/stage.go:26-27`).
- **The dev mock zeroes Active.** `devFleet.ts` serves every `/devices` call, including `current_release_id=<real id>`, and its devices point only at `rls_mock_*` releases, so a real release's Active card reads 0 with the mock on.
- **Requires upload shows only on rules that upload and delete.** The row renders it only when `require_upload` is set (`ReleaseFileRules.tsx:110`), which the spec sets exactly when the rule has an `upload` block (`api/gen/types.gen.ts:2433`). The whole row expands the rule, not just the arrow (`:55`). File-rule routes exist only on the CLI server (`servers/cli/endpoints/entry.go:175-179`).
- **`releases/upload-rule-list.png` still says "Upload Rules"**, and `releases/page.png` is still used by `staging-area.mdx`, `schemas/manage.mdx` and the quick start.
- **Device history lists queued deployments too.** The filter is target deployed or archived, and queued (`deployments/utils/search.ts:16-19`), so a deployment queued but never delivered is listed; only never-queued ones (staged, or archived from staging) aren't. The Deployment column also shows the description (`DeploymentColumn.tsx:23`).
- **Parent isn't only a patch.** The tooltip says "patched to create this deployment" (`DeploymentMetadata.tsx:119`), but the backend defaults the parent to the device's target deployment at creation (`services/deployments/create/create.go:188-198`), so editor deploys and `miru device stage` get one too.
- **DIFFERENT FORMAT is reachable.** `FileContent.tsx:29-35` calls it near-impossible, but a schema's instance format comes from its own filepath or `instance_format` (`backend services/config_schemas/create.go:309-326`), so a config type moving from `.json` to `.yaml` between releases shows it. The notice prints only the head's format (`alignFiles.ts:61`).
- **Linear parallel writes lagged.** Reads right after a batch of parallel `save_issue` calls showed stale descriptions, and a retry duplicated ENG-1398's section; it was rewritten to one copy. Write Linear issues one at a time and re-read before retrying.
