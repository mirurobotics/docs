Terms used below:

- **MDX** — Markdown with embedded JSX components. `.mdx` files here start with a YAML frontmatter block delimited by `---` lines; that block must stay first in the file.
- **Frontmatter** — the metadata block at the top of `agent.mdx`. Do not disturb it:

      ---
      title: "Agent"
      mode: "center"
      description: "Changelog and migration steps for the Miru Agent"
      ---

- **Entry** — one release in the changelog: an H1 version heading, an italic date line, an intro paragraph, then zero or more H2 sections, then a `---` separator before the next entry.

Changelog format rules, verified byte-for-byte against the existing file:

- Version headings are H1 (`# v0.10.1`). Section headings are H2 and appear in the order `## Breaking changes`, `## Features`, `## Fixes`, `## Improvements` when present.
- The date line is italic with a full month name and no ordinal: `*August 12, 2026*`. One blank line above and below.
- Entries are separated by `---` alone on a line, with exactly one blank line before and after. The file has no trailing `---`; it ends after the last bullet of the oldest entry.
- Bullets start with `- `, are sentence case, and have no trailing period.
- Em dashes are the literal character `—` (U+2014), used unspaced. Never write `--`: the `nodoubledash` lint rule flags two consecutive hyphens.
- Patch releases use a short form. Compare `v0.8.1`: a one-sentence intro of the form "… is a bug fix release that …" and a single `## Fixes` section. That is the model for v0.10.1. The intro is prefixed with "Miru Agent", matching the `v0.10.0` and `v0.9.0` entries.

Relevant lint rules (all in `tools/lint/linter/`): `headingcase` enforces sentence case but exempts version-looking headings, so `# v0.10.1` is fine and `## Fixes` is fine; `nodoubledash` as above; `importused` fails on an imported component that is unused in the body, which matters for `versions.mdx` (do not remove usages of `SupportedBadge`); `redirects` validates `docs.json` only and does **not** check inline markdown links. `cspell` checks prose spelling against `cspell.json` (at the docs repo root, not under `docs/`) — an unknown-word failure is fixed by rewording first, and only by adding the word to `cspell.json` if the word is genuinely necessary.

The inserted text ends with a `---` separator line so that the pre-existing `v0.10.0` entry keeps its own separator structure. This is the exact text to paste:

    # v0.10.1

    *August 12, 2026*

    Miru Agent `v0.10.1` is a bug fix release that hardens file uploads against transient network outages and makes agent shutdown flush all on-disk state.

    ## Fixes

    - Upload failures caused by network connection errors—including connection failures reaching AWS S3 and GCS—no longer count against a job's retry budget, so an unreachable backend or storage bucket can no longer cause an upload to be dropped; these failures now wait a flat 10 seconds and requeue behind the other pending uploads
    - Attempt every storage flush during shutdown even if an earlier step fails, so cached state is no longer lost when the device fails to report itself offline

    ---

The first bullet covers agent commits `a891e12` (classify S3/GCS connection failures as network errors across the executor boundary) and `7b18b05` (exempt network errors from attempt accounting, use a flat `base_secs` cooldown, requeue at the tail). "Flat 10 seconds" is the user-visible value of the default `backoff.base_secs: 10`; non-network failures keep the exponential 10s→120s backoff and the nine-attempt budget, which is unchanged and therefore not mentioned. The second bullet covers `106559e` (attempt all store shutdowns before returning the first error).
