Most Device API endpoints serve data the agent keeps on the device. Endpoints under `/cloud` are different. They return data that only Miru has, such as the calibrations the device has reported, and the agent fetches it from Miru on every request using the device's credentials.

Cloud endpoints were added in Device API [v0.2.5](/changelog/device-api#v0-2-5).

## Network access

A cloud endpoint works only while the agent can reach Miru. The agent keeps no copy of the data, so when Miru is unreachable the request fails with an error instead of returning stale or empty results. Retry once the device is back online.

See [Network requirements](/developers/agent/network) for the hosts the agent connects to.

## Scope

A cloud endpoint returns only the calling device's own data. Requesting another device's resource by its ID returns a not found error.

## Calibrations

| Endpoint | Python SDK | Description |
| -------- | ---------- | ----------- |
| <DeviceApiLink endpoint="cloud-calibrations/list">`GET /cloud/calibrations`</DeviceApiLink> | `client.cloud.calibrations.list()` | List the device's calibrations |
| <DeviceApiLink endpoint="cloud-calibrations/get">`GET /cloud/calibrations/{calibration_id}`</DeviceApiLink> | `client.cloud.calibrations.retrieve()` | Get one of the device's calibrations |

These endpoints let an application read back the [calibrations](/cfg-mgmt/concepts/calibrations) the device [reported](/cfg-mgmt/report-calibrations), for example after the device's computer is re-imaged or replaced. A calibration is listed only once the agent has uploaded it, so one reported while the device was offline appears after the device reconnects.

Calibration content is left out by default. Add `expand=content` to include it.

```python
from miru_device_sdk import Miru

client = Miru()
calibrations = client.cloud.calibrations.list(
    component=["kuka-arm"],
    role=["front-left"],
    expand=["content"],
)
for calibration in calibrations.data:
    print(calibration.aspect, calibration.content.data)
```

### Filtering by a missing role or aspect

The `role` and `aspect` filters accept `null`, which matches calibrations reported without a role or aspect. For example, `component=kuka-arm&role=null` lists the calibrations of a `kuka-arm` reported without a role.

Because of this, `null` is reserved and can't be [reported](/cfg-mgmt/report-calibrations) as a role or aspect.
