---
title: 'File system access'
description: 'What the Miru Agent needs to read and write on your devices, and how to grant it on Linux and Windows.'
---

The Miru Agent touches files on your devices in two cases:

- **[Configs](#configs)** — the agent **writes** config instances to disk when it deploys a release.
- **[Data uploads](#data-uploads)** — the agent **reads** the files a [file rule](/data-uploads/concepts/file-rules/overview) matches to upload them to your bucket, and deletes them afterwards if the rule has a [`retention`](/data-uploads/concepts/file-rules/rule-definition#retention) block.

Deploying config instances inside the agent's default config folder works out of the box. Any other path needs access granted to the agent's account. Linux and Windows use different permission models, so how you grant that access depends on the device's operating system:

| | Linux | Windows |
|---|---|---|
| Agent account | `miru` system user | `NT SERVICE\miru-agent` virtual account |
| Default config folder | `/srv/miru` | `%ProgramData%\Miru\configs` |
| Permission model | Mode bits (and optional ACLs) on each file and directory | Access control lists, usually inherited by files from their folder |
| Grant access with | `chmod`, `chgrp`, `usermod`, `setfacl` | `icacls` |
| Check access with | `check-miru-access.sh` | `icacls` |

## Configs

To deploy a config instance outside the default config folder, the agent needs to write the file and replace it atomically, which means creating and removing files next to it.

- **Linux** — read and write on the file, read, write, and execute on its directory, and execute on every directory above it. See [Configs on Linux](/developers/agent/filesys-access/linux#configs).
- **Windows** — modify access on the folder that holds the file. See [Configs on Windows](/developers/agent/filesys-access/windows#configs).

## Data uploads

To upload files, the agent needs to list the folder a file rule's glob matches in and read the matched files. Deleting files for a `retention` block needs more.

- **Linux** — read on the files, read and execute on their directory (plus write to delete), and execute on every directory above it. See [Data uploads on Linux](/developers/agent/filesys-access/linux#data-uploads).
- **Windows** — read and execute on the source folder (plus delete to delete). See [Data uploads on Windows](/developers/agent/filesys-access/windows#data-uploads).
