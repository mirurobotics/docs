Backups are configured per workspace from the dashboard. Each workspace writes its
backups to one bucket.

## Prerequisites

- A [bucket](/data-uploads/concepts/buckets) connected to Miru. Connect an [AWS S3](/data-uploads/connect-a-bucket/aws) or [GCS](/data-uploads/connect-a-bucket/gcs) bucket. Connecting a bucket needs the <PublisherBadge size="sm"/> role, and backups need no bucket permissions beyond the ones that connection grants.

## Enable backups  <AdminBadge />

<PlatformUnsupportedBadge />

<Steps>
  <Step title="Choose the bucket and prefix">
    In the Miru dashboard, navigate to the
    [Backups page](https://app.mirurobotics.com/settings/backups). Select the bucket, and
    edit the backup prefix from the default `miru-backups/`. 
  </Step>

  <Step title="Connect">
    Click **Connect**.

    Before connecting, Miru checks that it can write to the bucket by uploading an empty
    object under `<prefix>/.miru/probe/`. If the check fails, the page shows the error and
    nothing is saved.
  </Step>
</Steps>

The first backup starts within about an hour. Each later backup starts about a day after
the one before it.

A prefix can't start or end with `/`, or contain `*`, `?` or `$`. If more than one
workspace backs up to the same bucket, give each its own prefix, since archive names don't
include the workspace.

### Configure retention

Miru never deletes a backup, so archives build up until you remove them. To expire old
archives automatically, add a lifecycle rule for the backup prefix in
[AWS S3](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lifecycle-mgmt.html)
or [GCS](https://cloud.google.com/storage/docs/lifecycle). While backups keep running, an
age-based rule always leaves the newest archives in place.

### Run history <AdminBadge size="sm"/>

<PlatformUnsupportedBadge />

The [Backups page](https://app.mirurobotics.com/settings/backups) lists recent runs, newest
first, with each run's status and, once it succeeds, the size and key of its archive.

| Status | Meaning |
| ------ | ------- |
| `queued` | The run is waiting to start. |
| `running` | The run has started and hasn't finished. |
| `succeeded` | The archive was uploaded to the bucket. |
| `failed` | The run stopped before the archive was uploaded. |

When a run fails, the page shows why. The most common cause is a bucket role or service
account that no longer grants write access.

## Change where backups go  <AdminBadge />

<PlatformUnsupportedBadge />

On the [Backups page](https://app.mirurobotics.com/settings/backups), select a different
bucket or change the prefix, and click **Save**. Miru checks the new location the same way
before saving. Later backups go to the new location, and earlier archives stay where they
were written.

While the backup settings point at a bucket, you can't delete or
[archive](/data-uploads/concepts/buckets#archive-a-bucket) that bucket. Choose another
bucket, or [turn off backups](#turn-off-backups), first. A bucket that any backup has run
to can't be deleted, only archived.

## Turn off backups  <AdminBadge />

<PlatformUnsupportedBadge />

On the [Backups page](https://app.mirurobotics.com/settings/backups), clear the bucket and
click **Save**. No more backups run, and the archives already in your bucket stay where
they are.
