## Properties

<ParamField path="name" type="string">
  <EditableBadge />

  A human-readable display name, derived from the slug, so `realsense-d435` becomes `Realsense D435`.

  Examples: `Kuka Arm`, `Realsense D435`, `Robotiq 2f 85`
</ParamField>

<ParamField path="slug" type="string">
  <ImmutableBadge />

  A unique, code-friendly identifier that devices report calibrations with.

  Slugs are immutable and must satisfy the following constraints:

  - Contain only lowercase letters, digits, and hyphens (`-`)
  - Start and end with a lowercase letter or digit
  - Contain between 1 and 48 characters

  Examples: `kuka-arm`, `realsense-d435`, `robotiq-2f-85`

  A calibration reported with a `role` or `aspect` lands on the component whose slug joins them with `-`, such as `arm-left`. See [multiple units and parts](/cfg-mgmt/report-calibrations#multiple-units-and-parts).
</ParamField>

## Create a component

<PlatformUnsupportedBadge />

Components cannot be created directly. Instead, they are created when a device first [reports a calibration](/cfg-mgmt/report-calibrations) that uses them.
