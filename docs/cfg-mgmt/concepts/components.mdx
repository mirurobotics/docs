## Properties

<ParamField path="name" type="string">
  <EditableBadge />

  A human-readable display name, derived from the slug, so `front-camera` becomes `Front Camera`.

  Examples: `Arm`, `Front Camera`, `Gripper`
</ParamField>

<ParamField path="slug" type="string">
  <ImmutableBadge />

  A unique, code-friendly identifier that devices report calibrations with.

  Slugs are immutable and must satisfy the following constraints:

  - Contain only lowercase letters, digits, and hyphens (`-`)
  - Start and end with a lowercase letter or digit
  - Contain between 1 and 32 characters

  Examples: `arm`, `front-camera`, `gripper`
</ParamField>

<ParamField path="roles" type="[] Role">
  The purpose the component fills on a device, such as their positions on a robot arm or the sides of a gripper.

  A device with two arms might report them as `left` and `right`.

  Roles are optional, so a device with one arm, calibrated one way, reports only the component.

  Examples: `front-left`, `front-right`, `back-left`, `back-right`
</ParamField>

<ParamField path="aspects" type="[] Aspect">
  The parts of a unit that are calibrated separately.

  A camera might have the aspects `intrinsics` and `extrinsics`.

  Aspects are optional, so a device with one camera, calibrated one way, reports only the component.

  Examples: `intrinsics`, `extrinsics`
</ParamField>


## Create a component

<PlatformUnsupportedBadge />

Components, roles and aspects cannot be created directly. Instead, they are created when a device first [reports a calibration](/cfg-mgmt/report-calibrations) that uses them.
