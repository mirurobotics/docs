## Properties

<ParamField path="name" type="string">
  <EditableBadge />

  A human-readable display name. It defaults to one derived from the slug, so `realsense-d435` becomes `Realsense D435`.

  Examples: `Kuka Arm`, `Realsense D435`, `Robotiq 2f 85`
</ParamField>

<ParamField path="slug" type="string">
  <ImmutableBadge />

  A unique, code-friendly identifier that devices report calibrations with.

  Slugs are immutable and must satisfy the following constraints:

  - Contain only lowercase letters, digits, and hyphens (`-`)
  - Start and end with a lowercase letter or digit
  - Contain between 1 and 48 characters

  Examples: `kuka-arm`, `realsense-d435`, `robotiq-2f-85`

  Give each unit or separately calibrated part its own slug, such as `arm-left` or `realsense-d435-intrinsics`. See [multiple units and parts](/cfg-mgmt/report-calibrations#multiple-units-and-parts).
</ParamField>

## Create a component  <PublisherBadge />

<PlatformUnsupportedBadge />

**Agent**

A device creates a component when it first [reports a calibration](/cfg-mgmt/report-calibrations) that uses it. The component's name is derived from its slug.

**Dashboard**

Publishers can create a component in the dashboard, for example to list it in a [hardware manifest](/cfg-mgmt/concepts/hardware-manifests) before any device has calibrated it. To create a component, enter:

- **Slug** (required): must follow the [slug rules](#param-slug) and be unique within the workspace. It can't be changed later, and a device reporting a calibration with the same slug uses this component.
- **Name** (optional): leave it blank to use a name derived from the slug, so `realsense-d435` becomes `Realsense D435`. You can [change it](#edit-a-component) later.

## Edit a component  <PublisherBadge />

<PlatformUnsupportedBadge />

Publishers can change a component's name. Its slug never changes.
