## Properties
<ParamField path="content" type="object">
  <ImmutableBadge />

  The configuration values that are deployed to the device as a file, written in the config schema's instance format.
</ParamField>

<ParamField path="file path" type="string">
  <ImmutableBadge />

  The absolute file system path where the config instance is written on the device.

  Examples: `/srv/miru/configs/v1/motion-control.json`, `/srv/miru/configs/safety.yaml`
</ParamField>

<ParamField path="config schema" type="Config Schema">
  <ImmutableBadge />

  The [config schema](/cfg-mgmt/primitives/schemas/overview#properties) that the config instance must adhere to.

  Example: `SCH-FmoDN`
</ParamField>

## File formats

The formats a config instance may use are determined by the schema language of its [config schema](/cfg-mgmt/primitives/schemas/overview).

<SchemaFormats />

In practice, JSON Schema and CUE schemas accept JSON and YAML, while [opaque](/cfg-mgmt/primitives/schemas/languages/opaque) schemas additionally accept XML and plain text, since they do not validate instance content.

<Note>
  The instance format is normally inferred from the instance file path's extension. Plain text has no recognized extension, so a text config instance must declare `instance_format: text` in its opaque schema — otherwise schema creation fails.
</Note>

At deploy time, the Miru Agent writes the config instance to its instance file path exactly as authored, byte for byte. On-device applications read and parse the file themselves.
