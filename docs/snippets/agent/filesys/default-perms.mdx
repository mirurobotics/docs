<Tabs>
  <Tab title="Linux">
    During installation, the `miru` system user and group are created (no login shell). The
    agent process runs as `miru:miru` under systemd.

    By default, the agent creates and owns the following directories:

    | Path | Purpose |
    |------|---------|
    | `/var/lib/miru` | Agent state, credentials, device identity |
    | `/var/log/miru` | Log files (hourly rotation) |
    | `/srv/miru` | Deployed configuration instance files |

    The first two directories are only for internal use by the agent.

    The third directory is the default location for deploying config instances—reading or
    writing to any path inside `/srv/miru` is supported out-of-the-box, no additional
    configuration required.
  </Tab>
  <Tab title="Windows">
    The agent runs as a Windows service under the virtual account `NT SERVICE\miru-agent`. The account has no administrator rights.

    By default, the installer creates the following directories:

    | Path | Purpose |
    |------|---------|
    | `%ProgramData%\Miru` | Agent state, credentials, device identity |
    | `%ProgramData%\Miru\logs` | Log files (hourly rotation) |
    | `%ProgramData%\Miru\configs` | Deployed configuration instance files |

    The first two directories are only for internal use by the agent and are restricted to Local System, Administrators, and the agent's service account.

    The third directory is the default location for deploying config instances—writing to any path inside `%ProgramData%\Miru\configs` is supported out-of-the-box. 
    
    For security, only members of the local `Miru Agent Users` group can read from `%ProgramData%\Miru\configs`. 
  </Tab>
</Tabs>
