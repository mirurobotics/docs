<ParamField path="config type" required>
  The config type is a required annotation that identifies the config type to which a schema belongs. Below is the syntax for annotating a schema with a [config type slug](/cfg-mgmt/primitives/config-types#param-slug).

  <CodeGroup>

  ```yaml JSON Schema
  x-miru-config-type: "{config-type-slug}"
  ```

  
  ```cue CUE
  @miru(config_type="{config-type-slug}")
  ```

  
  ```yaml Opaque
  config_type: "{config-type-slug}"
  ```

  </CodeGroup>

  If the provided config type slug does not yet exist, it is automatically created. To edit a config type after creation, visit the [config types documentation](/cfg-mgmt/primitives/config-types#edit-a-config-type).

  Examples: `mobility`, `communication`, `perception`
</ParamField>

<ParamField path="schema language">
  The schema language declares the language that a schema is written in. This annotation applies to [Opaque](/cfg-mgmt/primitives/schemas/languages/opaque) schemas only, and is required for them.

  JSON Schema and CUE schemas have no schema language annotation. Their language is inferred from the schema file itself, so a `.cue` file is read as CUE, and a `.json` or `.yaml` file is read as JSON Schema unless it declares itself opaque.

  ```yaml Opaque
  language: "opaque"
  ```

  Because an opaque schema is written as JSON or YAML — the same formats as a JSON Schema — this annotation is what distinguishes the two.
</ParamField>

<ParamField path="instance file path">
  The instance file path is the absolute file system path where config instances for this schema are written on the device.

  <Warning>
    The Miru Agent ships with out-of-the-box access to `/srv/miru`. To deploy configs to a custom directory, please visit the [File system access](/developers/agent/filesys-access#configs) page.
  </Warning>

  This annotation declares the schema's single instance slot. It is optional and defaults to `/srv/miru/configs/{config-type-slug}.json`, or to `/srv/miru/configs/{config-type-slug}.yaml` when the schema is written in YAML. To write more than one file from one schema, declare [instance slots](#param-instance-slots) instead.

  <CodeGroup>

  ```yaml JSON Schema
  x-miru-instance-filepath: "/srv/miru/configs/{config-type-slug}.json"
  ```

  
  ```cue CUE
  @miru(instance_filepath="/srv/miru/configs/{config-type-slug}.json")
  ```

  
  ```yaml Opaque
  instance_filepath: "/srv/miru/configs/{config-type-slug}.json"
  ```

  </CodeGroup>

  Examples: 

      - `/srv/miru/configs/mobility.json`
      - `/home/myapp/configs/communication.yaml`
      - `/var/lib/myapp/configs/safety.yaml`


</ParamField>

<ParamField path="instance slots">
  An instance slot is a distinct file system destination for this schema. Declare several slots to write several config instances from a single schema — one per slot — instead of maintaining a near-identical config type for each destination. Each slot has a `key`, a `name`, a `filepath`, a `required` flag, and an optional `description`.

  <Warning>
    A schema may declare an instance file path or instance slots, but never both. Declaring both is an error.
  </Warning>

  This annotation is optional. Omitting it is equivalent to declaring a single slot at the instance file path, which is the shorthand for the single-slot case.

  <CodeGroup>

  ```yaml JSON Schema
  x-miru-instance-slots:
    - key: "left-arm"
      name: "Left Arm"
      filepath: "/srv/miru/configs/v1/left-arm.json"
      required: true
      description: "Config for the left arm controller"
    - key: "right-arm"
      name: "Right Arm"
      filepath: "/srv/miru/configs/v1/right-arm.json"
      required: false
  ```

  
  ```cue CUE
  @miru_instance_slot(key="left-arm", name="Left Arm", filepath="/srv/miru/configs/v1/left-arm.json", required=true, description="Config for the left arm controller")
  @miru_instance_slot(key="right-arm", name="Right Arm", filepath="/srv/miru/configs/v1/right-arm.json", required=false)
  ```

  
  ```yaml Opaque
  instance_slots:
    - key: "left-arm"
      name: "Left Arm"
      filepath: "/srv/miru/configs/v1/left-arm.json"
      required: true
      description: "Config for the left arm controller"
    - key: "right-arm"
      name: "Right Arm"
      filepath: "/srv/miru/configs/v1/right-arm.json"
      required: false
  ```

  </CodeGroup>

  Slot file paths must be unique across every schema in the release. Unless the schema also declares an [instance format](#param-instance-format), every slot file path must imply the same format.
</ParamField>

<ParamField path="instance format">
  The instance format declares the format that config instances for this schema are deployed as on the device.

  JSON Schema and CUE schemas accept `json` and `yaml`. [Opaque](/cfg-mgmt/primitives/schemas/languages/opaque) schemas accept a wider set — `json`, `yaml`, `xml`, and `text` — since their instance content is not validated.

  This annotation is optional. When it is omitted, the format is inferred from the extension of the schema's first slot file path, and every slot file path must then imply that same format. Under the default instance file path the instance format therefore defaults to `json`, or to `yaml` when the schema is written in YAML and takes the YAML default path. Declaring this annotation removes the matching requirement: the slot file paths' extensions are no longer compared.

  <CodeGroup>

  ```yaml JSON Schema
  x-miru-instance-format: "yaml"
  ```

  
  ```cue CUE
  @miru(instance_format="yaml")
  ```

  
  ```yaml Opaque
  instance_format: "xml"
  ```

  </CodeGroup>

  Examples: `json`, `yaml`, `xml`, `text`
</ParamField>
