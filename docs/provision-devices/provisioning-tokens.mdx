To programmatically provision devices, Miru offers provisioning tokens. If you already manage hosts with Ansible, use the official [Ansible collection](/provision-devices/ansible) instead of minting tokens yourself.

Provisioning tokens are only supported when installing `miru-agent` version `v0.9.0` or later. If installing a version that precedes `v0.9.0`, continue to use the [provisioning script](/provision-devices/provisioning-script).

Unlike the dashboard, which requires manual interaction with the web interface for each device, provisioning tokens allow you to:

- **Provision multiple devices** without manual intervention
- **Integrate with existing infrastructure** management tools and workflows
- **Use in headless environments** where a web browser isn't available

## Install the `miru-agent` package

Before provisioning a device via provisioning tokens, you must first install the `miru-agent` package onto the target machine.

## Create a provisioning token

Provisioning tokens are created via the <PlatformApiLink endpoint="provisioning-tokens/create">Platform API</PlatformApiLink> endpoint using [API keys](/admin/apikeys).

**Create the API key**

If you don't have an API key, follow the instructions for [creating an API key](/admin/apikeys#create-an-api-key). The API key requires the `devices:provision` and `provisioning_tokens:write` scopes.

**Create the token**

Once you have an API key, you can create a token using the following code samples. Keep in mind that tokens are short-lived (expire in 5 minutes) and one-time use only.

<CodeGroup>

```bash bash
export MIRU_API_KEY=<api-key>

curl --request POST \
  --url https://api.mirurobotics.com/beta/provisioning_tokens \
  --header 'Miru-Version: 2026-08-17.everglades' \
  --header "X-API-Key: $MIRU_API_KEY"
```

```powershell powershell
$env:MIRU_API_KEY = "<api-key>"; `
$provisioningToken = Invoke-RestMethod -Method Post `
  -Uri "https://api.mirurobotics.com/beta/provisioning_tokens" `
  -Headers @{ "Miru-Version" = "2026-08-17.everglades"; "X-API-Key" = $env:MIRU_API_KEY }; `
$provisioningToken.token
```

```python python
import os
from miru_platform_sdk import Miru

client = Miru(
    api_key=os.environ.get("MIRU_API_KEY"), 
)
provisioning_token = client.provisioning_tokens.create()
# access token via provisioning_token.token
```

</CodeGroup>

## Provision the device

  <Tab title="Linux">

    ```bash
    sudo -u miru MIRU_PROVISIONING_TOKEN=<token> \
      /usr/sbin/miru-agent provision
    ```

    The command can be broken into the following components:

    <CmdBreakdownLinux />
  </Tab>
  <Tab title="Windows">
    After retrieving the provisioning token, run the following commands from PowerShell opened with **Run as administrator**. Make sure to replace `<token>` with the actual token.

    ```powershell
    $env:MIRU_PROVISIONING_TOKEN = "<token>"; `
    & "$env:ProgramW6432\Miru\Agent\miru-agent.exe" provision; `
    Remove-Item Env:MIRU_PROVISIONING_TOKEN
    ```

    The commands can be broken into the following components:

    <CmdBreakdownWindows />

    Administrator rights are required because the agent's state folder, `%ProgramData%\Miru\Agent`, is restricted to Local System, Administrators, and the agent's service account.
  </Tab>
</Tabs>

Provisioning performs the following actions:

1. **Creates or activates the device** - creates a new device if the provided name does not exist, or activates an existing `inactive` device with that name. If the named device has already been activated (`online`, `offline`, and so on), the command fails. To attach a machine to an already-activated device, use the [reprovision](/provision-devices/reprovision) flow.
1. **Provisions the device** - registers the agent with the Miru control plane.

### Troubleshooting

If the machine you're provisioning on has already been provisioned, the provisioning command is treated as a no-op and exits successfully.

To reassociate the machine with an existing Miru device, follow the [reprovisioning](/provision-devices/reprovision) documentation.

To provision the machine as a brand new Miru device (never been provisioned in Miru before), first [uninstall](/developers/agent/install#uninstall) the `miru-agent` package before continuing with the provisioning process. On Windows, also delete `%ProgramData%\Miru`, which holds the device's identity and is kept when the agent is uninstalled.

### Arguments

The provision command supports the following parameters to tune your installation:

<ParamField path="--device-name" type="string">
  The name of the device in the Miru dashboard; defaults to the machine's hostname (the output of `hostname`).

  Default: `hostname`
</ParamField>
