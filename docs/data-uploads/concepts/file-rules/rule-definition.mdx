File rules are defined as a single YAML file in your Git repository:

```yaml
name: Robot Logs

source:
  glob: "/var/log/robot/*.log"
  stability_window_secs: 60

# optional block
upload:
  collection_slug: robot-logs
  bucket: my-uploads-bucket
  path: "logs/{device_id}/{upload_id}/{file_name}"

# optional block
retention:
  ttl_secs: 604800
  require_upload: true
```

Rule files reference the rule's upload collection by its slug
(`upload.collection_slug`) and the bucket by name (`upload.bucket`).

File rules use `source.glob` to select the files that Miru manages on a device. The
Miru Agent evaluates the pattern on every scan, so files that appear after a rule is
deployed can still match it.

### Glob patterns

File rule glob patterns select the files that Miru manages on a device.

Every pattern must:

- Be absolute (e.g. start with `/` on Linux or a drive letter such as `C:\` on Windows)
- Be at most 1024 bytes and contain no control characters
- Contain no `.` or `..` segments or empty segments (`//` or a trailing `/`)

Each rule accepts one pattern. To match files that no single pattern covers, define a
rule for each pattern.

**Supported syntax**

| Syntax | Matches |
| --- | --- |
| `*` | any characters within one path segment; never crosses a separator (e.g. `/`) |
| `**` | zero or more directories at any depth; must be a whole path segment on its own (`/var/log/**/*.log` is valid but `**.log`, `run**`, and `***` are invalid) |
| `?` | one character |
| `[abc]`, `[a-z]` | one character from the set or range |
| `[!abc]`, `[!a-z]` | one character not in the set or range |
| `{key}` | like `*`, and records the matched text under a capture key; see [Glob captures](#glob-captures) |

Brace expansion is not supported: a brace group containing a comma, such as `{a,b}`,
matches literally. A brace group without a comma, such as `{Recording}` or `{}`, is read
as a capture and must be valid (see [Glob captures](#glob-captures)). 

Backslash escapes
(`\*`) and extended patterns such as `!(x)` are not supported. On Linux, backslashes
also match literally; on Windows, `\` is a path separator.

**Examples**

<Tabs>
  <Tab title="Linux">

    | Pattern | Matches |
    | --- | --- |
    | `/var/log/robot/*.log` | `.log` files directly inside `/var/log/robot` |
    | `/var/log/robot/*/*.log` | `.log` files exactly one directory below `/var/log/robot` |
    | `/var/log/robot/**/*.log` | `.log` files in `/var/log/robot` and all of its subdirectories |
    | `/var/log/robot/**/*` | Every file in `/var/log/robot` and all of its subdirectories |
    | `/var/log/robot/run-[0-9].log` | `run-0.log` through `run-9.log` in `/var/log/robot` |

  </Tab>
  <Tab title="Windows">

    | Pattern | Matches |
    | --- | --- |
    | `C:\ProgramData\App\logs\*.log` | `.log` files directly inside `C:\ProgramData\App\logs` |
    | `C:\ProgramData\App\logs\*\*.log` | `.log` files exactly one directory below `C:\ProgramData\App\logs` |
    | `C:\ProgramData\App\logs\**\*.log` | `.log` files in `C:\ProgramData\App\logs` and all of its subdirectories |
    | `C:\ProgramData\App\logs\**\*` | Every file in `C:\ProgramData\App\logs` and all of its subdirectories |
    | `C:\ProgramData\App\logs\run-[0-9].log` | `run-0.log` through `run-9.log` in `C:\ProgramData\App\logs` |

  </Tab>
</Tabs>

**Matching behavior**

- a trailing `**` matches only directories, so `/var/log/robot/**` matches no files — use `/var/log/robot/**/*` instead
- only regular files match; a directory never matches even if its name does
- symbolic links to files and directories are followed
- matching is case-sensitive (`*.log` does not match `APP.LOG`); on Windows, path segments without wildcards follow the file system and match regardless of case, but segments with wildcards remain case-sensitive
- `*` and `**` match hidden files and directories whose names start with `.`
- keep the part of the pattern before the first wildcard as specific as possible; a broad pattern such as `/**/*.log` walks large parts of the file system on every scan

<Warning>
  You must grant the Miru Agent read access to matching files and their containing
  directories. Files in directories the agent can't read are silently skipped. See
  [File system access on Linux](/developers/agent/filesys-access/linux#data-uploads) or [Windows](/developers/agent/filesys-access/windows#data-uploads) for details.
</Warning>

### Glob captures

A capture is a `{key}` placeholder in a glob, where `key` is the capture key. It matches exactly like the `*` wildcard operator but records the matched text under that key. The captured value can then be used elsewhere.

**Examples**

Captured values have two main uses:

<AccordionGroup>
  <Accordion title="Configure the upload path">
    Reference a capture in [`upload.path`](/data-uploads/concepts/file-rules/rule-definition#param-path) as `{key}`. The matched text is filled in with the capture's value on upload.

    ```yaml highlight={4,9}
    name: Recordings

    source:
      glob: "/data/recordings/{recording}/*"

    upload:
      collection_slug: recordings
      bucket: my-uploads-bucket
      path: "{device_id}/{recording}/{upload_id}/{file_name}"
    ```

    Source file: `/data/recordings/run_42/camera.mcap`

    Upload path: `dvc_123/run_42/upl_123/camera.mcap`
  </Accordion>

  <Accordion title="Group related uploads into a bundle">
    Specify capture keys in the [`upload.bundle`](/data-uploads/concepts/file-rules/rule-definition#param-bundle) field. Uploads from the same device and upload collection with matching capture values are [bundled](/data-uploads/concepts/upload-bundles).

    <RecordingsBundle />

    For more information on bundles, see [Upload bundles](/data-uploads/concepts/upload-bundles).
  </Accordion>
</AccordionGroup>

**Key rules**

Capture keys must:

- Start with a lowercase letter
- Contain only lowercase letters, digits, and `_`
- Be unique within the glob
- Not reuse a built-in upload path [variables](/data-uploads/concepts/file-rules/rule-definition#param-path)
- Be used in the [upload path](/data-uploads/concepts/file-rules/rule-definition#param-path) or [upload bundle](/data-uploads/concepts/file-rules/rule-definition#param-bundle)

A path segment holds at most one capture, and the rest of that segment must be constant
text, with no `*`, `?`, `[`, `\`, or other braces. A capture may not have `**` segments
both before and after it.

**Invalid examples**

| Pattern | Reason |
| --- | --- |
| `/data/{recording}_*.mcap` | `*` in a capture's segment |
| `/data/{session}{run}/*` | Two captures in one segment |
| `/data/**/{recording}/**/*` | `**` before and after the capture |
| `/data/{Recording}/*` | The key must start with a lowercase letter |
| `/data/{file_name}/*` | Reuses a built-in variable |

**Valid examples**

- `/data/recordings/{recording}/*`
- `/data/{session}/run_{run}.mcap`
- `/data/{session}/**/*.mcap`
- `/data/**/run_{run}.mcap`
- `/data/{session}/cam?.mcap`
- `/data/{session}/run-[0-9].mcap`
- `/data/{session}/cam[012].mcap`
- `/data/{session}/[!._]*`
