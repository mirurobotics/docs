A bundle is a group of related [uploads](/data-uploads/concepts/uploads) from one
device, such as every file from one recording or run. 

## Properties

<ParamField path="device" type="Device">
  <ImmutableBadge />

  The [device](/concepts/devices/overview) whose uploads the bundle groups.
</ParamField>

<ParamField path="upload collection" type="Upload Collection">
  <ImmutableBadge />

  The [upload collection](/data-uploads/concepts/upload-collections) whose uploads the
  bundle groups.
</ParamField>

<ParamField path="capture_keys" type="string[]">
  <ImmutableBadge />

  The capture keys from [upload.bundle](/data-uploads/concepts/file-rules/rule-definition#param-bundle) of the file rule that created the bundle. 
  
  Capture keys do not affect membership, only captured values do. See [Membership](#membership).

  Example: `["mission", "run"]`
</ParamField>

<ParamField path="capture_values" type="string[]">
  <ImmutableBadge />

  The captured values that identify the bundle. 
  
  Together with the device and upload collection, these values are the bundle's
  identity: no two bundles share all three. See [Membership](#membership).

  Example: `["mission_123", "run_03"]`
</ParamField>

## Membership

Uploads from the same device and the same upload collection whose captured values match,
in the order `upload.bundle` lists them, share one bundle. This holds across file rules
and over time: a file that matches later joins the existing bundle.

- Capture keys do not affect matching. Rules that use different capture keys share
  a bundle if they list them in the same order with the same values.
- Order matters. Session `03` with run `05` and session `05` with run `03` are different
  bundles.
- Bundles never span devices or upload collections.

## Multiple rules

Related files sometimes need different rules, for example because `.yaml` files need a
shorter stability window than `.mcap` files:

```yaml
name: Run Recordings

source:
  glob: "/data/runs/run_{run}.mcap"

upload:
  collection_slug: runs
  bucket: my-uploads-bucket
  path: "runs/{device_id}/{bundle_id}/{upload_id}/{file_name}"
  bundle:
    - run
```

```yaml
name: Run Metadata

source:
  glob: "/data/runs/run_{id}.yaml"
  stability_window_secs: 5

upload:
  collection_slug: runs
  bucket: my-uploads-bucket
  path: "runs/{device_id}/{bundle_id}/{upload_id}/{file_name}"
  bundle:
    - id
```

`run_42.mcap` and `run_42.yaml` join one bundle because both rules list one capture with
the value `42` and use the same upload collection, even though their capture keys differ.

The same works for one rule per sensor folder, for example `/data/{session}/camera/*`
and `/data/{session}/lidar/*`, both bundled by `session`.
